# Requirements: the web product's problem context and documentation

EARS (Mavin et al., RE'09, doi:10.1109/RE.2009.9). Every requirement names the gate that fails when it is violated.
This feature holds the executive view standard (CAOS_MANAGE `conventions/problem-context-first.md`, Felipe 2026-10-12):
the executive view is one data file the shell renders, `content/executive.json`, valid against the shell's
`executive.schema.json`, with three illustrations; the design document names the file and restates nothing. The
page-side areas of the technical view (ADR-0017 section 2.1) are measured by the shell's gate and are added here when
the template's pages adopt them.

| ID | Requirement | Gate |
|---|---|---|
| WB-001 | THE design document SHALL carry an Executive brief section right after the problem and non-goals that names the data file in a `Data file: content/executive.json` line and restates nothing of the executive view (no part heading, list, table or sentence of the file). | `tests/test_spec_guards.py::test_brief_missing_section_fails_and_points_at_the_guide` (and, for the place, the line and the restating, `test_brief_at_the_end_of_the_sdd_fails`, `test_brief_without_the_data_file_line_fails`, `test_brief_that_restates_the_view_in_structure_fails`, `test_brief_that_copies_a_sentence_of_the_file_fails`) |
| WB-002 | THE product SHALL commit `content/executive.json` valid against the shell's `executive.schema.json`, and WHEN the file is missing, is not JSON or breaks the schema THE check SHALL fail naming the file and the field path of each violation. | `tests/test_spec_guards.py::test_view_a_file_that_breaks_the_schema_names_the_field_path` (and `test_view_missing_file_fails_naming_it_and_the_guide`, `test_view_a_file_that_is_not_json_fails`) |
| WB-003 | WHEN the shell's schema is not installed (`frontend/node_modules` absent) THE check SHALL fail and say so, never pass without having validated the file. | `tests/test_spec_guards.py::test_view_without_the_shell_schema_fails_instead_of_passing` |
| WB-004 | THE three illustration files named by `content/executive.json` SHALL exist under `frontend/public/` as SVG documents with a viewBox, and a path that leaves the site SHALL fail. | `tests/test_spec_guards.py::test_view_a_missing_illustration_file_is_named` (and `test_view_an_illustration_that_is_not_an_svg_with_a_viewbox_fails`, `test_view_an_illustration_path_that_leaves_the_site_fails`) |
| WB-005 | THE executive view SHALL give every figure (the why-now figure and the proof of each outcome) one source by field path, and no source for a field that is not a figure. | `tests/test_spec_guards.py::test_view_a_figure_without_a_source_fails` (and `test_view_a_source_for_a_field_that_is_not_a_figure_fails`) |
| WB-006 | THE Introduction SHALL render the shell's `ExecutiveView` from `content/executive.json` as its first and default view, with the technical view second and nothing else beside the executive view. | `frontend/src/pages/Introduction.test.tsx::the Introduction opens on the executive view rendered from content/executive.json` |
| WB-007 | THE example's `content/executive.json` SHALL satisfy the shell's `validateExecutive` (writing limits in both languages, a source for every figure, no 4 C's while `FOUR_CS` is empty), and its three illustrations SHALL be coloured only with theme tokens, declare no chart, carry labels in English and Spanish and share the setting of the problem and the solution. | `frontend/src/content/executive.test.ts::the example executive data is valid` (and `the example illustrations use only theme tokens and carry both languages`) |
